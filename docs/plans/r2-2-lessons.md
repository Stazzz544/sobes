# R2-2 — конспекты по тегам: план

Составлен 14.10.2026 как передача в новую сессию. Размер L: инфраструктура + 71 конспект (по одному на тег) RU+EN.

## Что получает пользователь

На каждый тег (замыкания, event loop, дженерики…) — 1–2 экрана теории: короткое введение, объяснение с кодом и схемами, «Запомнить» (3–5 пунктов), источники и кнопка «Потренировать» (практика по этому тегу). Открывается из разбора вопроса и из «Слабых мест». Бесплатно.

## Модель данных

Конспекты живут в `entities/question` рядом с тегами: им нужны `ExplanationBlock`, `DiagramPlayer` и `DIAGRAMS`, а импорт между сущностями запрещён FSD.

```ts
// entities/question/model/types.ts
export type Lesson = {
  tag: TagId;
  summary: LocalizedText;          // 1–2 предложения: подзаголовок и превью
  blocks: ExplanationBlock[];      // те же text / code / diagram, что в разборе
  keyPoints: LocalizedText[];      // «Запомнить», 3–5 пунктов
  sources: QuestionSource[];
};
```

- Данные: `entities/question/lessons/<topic>.ts` → `LESSONS_BY_TAG: Partial<Record<TagId, Lesson>>` (Partial — пока наполняем по темам; когда все 71 готовы, сделать полным `Record`, и компилятор поймает пропуски).
- Заголовок — из `TAGS[tag].title`, тема — `TAGS[tag].topic`, в конспекте не дублировать.

## UI

1. Вынести рендер блоков из `ExplanationView` в `ExplanationBlocks({ blocks })` (тот же файл/слайс), `ExplanationView` использует его. Без изменения вида разбора.
2. Экран `app/lesson/[tag].tsx` → виджет `widgets/lesson-view`: заголовок тега, `summary`, `ExplanationBlocks`, карточка «Запомнить» (список), источники (как в разборе), кнопка «Потренировать» → `/quiz?mode=practice&topic=<TAGS[tag].topic>&tag=<tag>`. Нет конспекта — `EmptyState`.
3. Точки входа (только если конспект есть):
   - разбор вопроса (`ExplanationView` / `answer-feedback` / `question-review`): ряд чипов «Конспект: <тег>» по `question.tags`;
   - статистика, «Слабые места»: вторая кнопка рядом с «Потренировать»;
   - итог сессии (`session-summary`, список ошибок): чип тега ведёт в конспект.
4. Тексты UI — `lesson.*` в `ru.ts`/`en.ts` (`keyPoints`, `practice`, `open`, `notFound`).
5. Проверка: 360 dp, light/dark, разные акценты; схемы и код в конспекте — как в разборе.

## Проверка контента (`verify-content`)

- Каждый конспект: `tag` есть в `TAGS`; файл темы совпадает с `TAGS[tag].topic`; RU и EN непустые во всех `LocalizedText`; `keyPoints` 3–5; ≥ 1 источник; кириллица в `code` запрещена (как у вопросов); `diagram` есть в `DIAGRAMS`.
- `--links` проверяет и источники конспектов.
- Код в конспектах — по желанию `verify: js-output` на блок (вывод совпадает с комментарием/подписью). Решить при реализации: если сложно, достаточно ручной сверки + правило в content-guidelines.
- В `docs/content-guidelines.md` — раздел «Конспекты»: объём (до ~350 слов на язык), структура, тон, первоисточники, не дублировать разборы вопросов, а давать модель, из которой ответы следуют.

## Аналитика

`lesson_opened { tag, source: 'review' | 'stats' | 'summary' }` и `lesson_practice { tag }` — полезно для R2-3 и R1-4. Новое событие = правка политики (`site/privacy/`) до выпуска. Решение: добавить вместе с инфраструктурой и обновить политику в том же коммите.
