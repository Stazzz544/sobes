# R3-1 — контент-паки отдельно от релиза: план

Составлен 15.10.2026. Размер L, делается в три шага, каждый — отдельный коммит.

## Зачем

Сейчас вопросы вшиты в бандл: новый вопрос или исправленная опечатка доходят до пользователя только с новым релизом в RuStore, а модерация — дни. Паки позволяют обновлять банк без релиза.

## Что входит в пак

Один пак на направление (`frontend`): вопросы, конспекты, глоссарий, диаграммы. Темы, теги, пути, цвета и логотипы остаются в коде — пак не может добавить новую тему или тег. Это сознательно: новая тема — это и UI (логотип, акцент), и она всё равно выходит релизом.

```
site/packs/v1/manifest.json   { schema: 1, packs: { frontend: { file, appVersion, builtAt, questions, lessons, size, sha256 } } }
site/packs/v1/frontend.json   { schema: 1, appVersion, builtAt, questions, lessons, glossary, diagrams }
```

- `v1` и `schema` — версия формата. Приложение принимает только знакомую схему; несовместимое изменение формата → `v2` рядом, старые приложения продолжают читать `v1`.
- `appVersion` — версия приложения, из исходников которого собран пак. Каждая правка контента и так поднимает версию (скилл release-notes), поэтому `appVersion` упорядочивает паки без отдельного счётчика.
- Паки не коммитятся: их собирает workflow Pages из исходников при каждом пуше в `main`, после `verify:content`.

## Шаг 1 — сборка и публикация (без изменений в приложении)

- `scripts/build-packs.ts` (`npm run build:packs`): берёт `QUESTIONS`, `LESSON_GROUPS`, `GLOSSARY`, `DIAGRAMS` из исходников, пишет пак и манифест в `site/packs/v1/` (по умолчанию) с `sha256` и размером.
- `.github/workflows/pages.yml`: триггер — пуш в `main` по `site/**`, контенту, скрипту и workflow; шаги `npm ci` → `npm run verify:content` → `npm run build:packs` → публикация `site/`. Битый контент не публикуется.
- `site/packs/` — в `.gitignore`.
- Проверка: `curl https://stazzz544.github.io/sobes/packs/v1/manifest.json`.

## Шаг 2 — приложение читает паки

- Реестр контента в `entities/question`: `getQuestions()`, `getQuestionById()`, `getLessonGroups()`, `getLessonByTag()`, `getGlossaryTerm()`, `getDiagram()` вместо констант `QUESTIONS` / `QUESTIONS_BY_ID` / `LESSON_GROUPS` / `LESSONS_BY_TAG` / `GLOSSARY` / `DIAGRAMS` у потребителей (≈15 файлов). По умолчанию реестр отдаёт встроенный банк.
- Применение — при холодном старте, пока висит сплэш: прочитать пак из `documentDirectory` (`expo-file-system`, через `npx expo install`), проверить `schema`, что `appVersion` пака **новее** версии приложения, отфильтровать то, что эта версия не умеет показать (неизвестные тема, тег, `kind`, тип блока разбора, диаграмма), и подменить банк. Любая ошибка → встроенный банк. Скачанное обновление применяется на следующем запуске — как OTA, без перерисовки на лету.
- Фоновая проверка после старта (не чаще раза в 12 часов): манифест → если пак новее и того, что в кэше, и встроенного — скачать, проверить `sha256` и число вопросов, атомарно записать (временный файл → `move`). Таймаут, без повторов в цикле, без ошибок на экране.
- Прогресс привязан к id вопросов: удалённый из пака вопрос просто перестаёт попадать в выборки (так уже работает с удалёнными вопросами), его статистика не мешает.
- В «О приложении»: «Банк вопросов: N · обновлён ДД.ММ».

## Шаг 3 — политика и стор

- `site/privacy/`: приложение раз в 12 часов скачивает обновления вопросов с GitHub Pages; GitHub при этом видит IP и технические данные запроса, как при открытии сайта; данных о пользователе запрос не содержит.
- `docs/store/`: в описание — «вопросы обновляются без обновления приложения».
- Анкета данных RuStore (R1-5) — дополнить при заполнении.

## Риски

- Старое приложение получает контент нового формата → фильтр неизвестного + `schema`. Проверить вручную: собрать пак с вопросом неизвестного `kind` и убедиться, что старая сборка его отбрасывает.
- Битый или обрезанный файл → проверка `sha256` до записи, `JSON.parse` в `try`, при старте — встроенный банк.
- Размер: пак ≈ размер JSON банка (сотни КБ после gzip, Pages сжимает сам); качаем только при новой версии.
- Платные паки в открытой статике не спрячешь — решается в точке Б, вне этого пункта.
