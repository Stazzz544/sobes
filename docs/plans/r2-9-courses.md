# Курсы из пошаговых уроков: материал → тест по прочитанному (пилот «Стейт-менеджмент»)

## Context

Фокус-группа учеников хочет такой поток обучения: выбрать тему → изучить материал с картинками, примерами и анимациями → пройти тест, где вопросы проверяют **ровно прочитанное**.

**Что есть сейчас:**
- Конспект на тег (122 шт.): 2–4 блока текста или кода, схемы — только в 10 уроках, картинок нет.
- Кнопка «Потренироваться» берёт все вопросы тега (до 26). Многие из них про то, чего в конспекте нет.
- Связь урока с вопросами — только через `question.tags`. Привязки вопроса к разделу урока нет.
- Путь по теме засчитывает раздел, когда отвечены все вопросы тега на 80%.

**Что решил владелец:**
- Тема — это курс из уроков: тест после каждого урока и итоговый тест курса.
- Урок — пошаговые экраны.
- Уроки не запираются, следующий рекомендуется.
- Пилот: тема `state`, «Стейт-менеджмент», 6 уроков. Остальные 116 конспектов пока работают как раньше.

## Решения

### 1. Формат урока — объединение типов, обратная совместимость

Файл `src/entities/question/model/types.ts`:
- `Lesson = ClassicLesson | StepLesson`. У старых уроков поле `format` не задано, `StepLesson` получает `format: 'steps'` и `steps: LessonStep[]`.
- `LessonStep = { id, title, blocks: LessonBlock[] (1–3), test: string[] }`, где `test` — 1–2 id вопросов, которые проверяют этот шаг.
- Тест урока — это все `step.test` по порядку шагов. Так связь «вопрос → шаг» задана самой структурой, и при ошибке можно предложить «Перечитать шаг N».
- `LessonBlock = ExplanationBlock | { type: 'illustration'; illustration; caption? } | { type: 'check'; check: InlineCheck }`.
- `InlineCheck` — «Проверь себя»: 2–4 варианта, пояснение. В банк вопросов и в статистику не пишется.
- Новые блоки разрешены только в уроках. Разборы вопросов не трогаем, иначе старые версии приложения выкидывали бы сами вопросы.
- `summary` становится вводным текстом урока. `keyPoints` и `sources` переезжают на финальный экран урока «Запомнить» перед кнопкой «Начать тест».
- Итоговый тест курса задаётся в `lessons/courses.ts`: `COURSES: Partial<Record<TopicId, Course>>`. `Course = { topic, final: { question, tag, step }[] }`, порядок уроков — `TOPIC_PATHS`.
- Новые хелперы в `src/entities/question/lib/lesson.ts`:
  - `isStepLesson`;
  - `getLessonTestIds` — отбрасывает id, которых нет в банке;
  - `findQuestionStep(questionId)` — чтобы разбор любого вопроса вёл на «Урок · шаг N».
- В реестр `model/content.ts` добавляем `illustrations` и `coursesByTopic`, геттеры `getIllustration` и `getCourse`.

### 2. Иллюстрации — SVG-строкой в контенте, рендер через `SvgXml`

- Пакет `react-native-svg` 15.12 уже установлен.
- Цвета пишутся только токенами `{{color.X}}`, они подставляются из `useTheme().colors`. Так картинка сама подстраивается под светлую и тёмную тему и под акцент темы.
- Подписи пишутся токенами `{{label.Y}}`, тексты лежат в `labels` (RU/EN) и экранируются при подстановке.
- Такие картинки доезжают паком без релиза, весят 1–4 КБ и не требуют отдельных файлов под каждую тему.
- Чистая функция `lib/illustration.ts` → `renderIllustration(ill, colors, locale)`; её же вызывает verify-content. Компонент `ui/illustration-view.tsx`: `aspectRatio` берётся из `viewBox`, `accessibilityLabel` — из `alt`.
- Данные лежат в `data/illustrations.ts`, `IllustrationId` — закрытый union, как `DiagramId`.

### 3. Анимации — расширяем `DiagramPlayer` вариантом `layout: 'tree'`

- В `DiagramLane` добавляется необязательное поле `parent`. Дерево рисуется с отступами по глубине, узлы окрашиваются по тону, активный узел выделяется, переходы между шагами — через `LinearTransition`.
- Покрывает темы курса: проп-дриллинг и композиция, подъём состояния, перерисовки от контекста, подписка селектором, структурное разделение, `combineReducers`.
- Для остального хватает существующих `chain` и `columns`. Lottie не используем.

### 4. Прогресс — `$learning` в `entities/progress`

- Ключ хранения `sobes_learning_progress`.
- По уроку храним `seenSteps`, `lastStep`, `finishedAt` и результат теста `{ attempts, bestRatio, lastRatio, passedAt, lastAt }`. По курсу — результат итогового теста.
- Загружается в `loadProgressFx` вместе с остальным и очищается при `progressReset`. Только `sample`, всё в модели.
- Отметка «пройден» навсегда: `passedAt` при результате ≥ 80%.
- `getPathProgress(topic, stats, learning)`:
  - урок в новом формате считается пройденным, если сдан тест **или** выполнено старое правило по тегу — так прогресс у текущих пользователей не откатится;
  - старые уроки считаются как раньше.
- Достижения (`full-path`, `first-unit`) получают `$learning`, смысл достижений не меняется.

### 5. Экраны и навигация (новых маршрутов не нужно)

**Урок: `/lesson/[tag]`.** `LessonView` выбирает между новым `lesson-stepper.tsx` и прежним конспектом.
- Сверху полоса прогресса и «Шаг 3 из 7», в шапке «Урок 2 из 6».
- Кнопки «Назад» и «Далее»; свайп — позже, после проверки конфликта с горизонтальным скроллом в `CodeBlock`.
- Финальный экран: «Запомнить», источники, кнопка «Начать тест · N» и второстепенная «Потренироваться по теме».
- Параметр `?step=` открывает нужный шаг; `&from=test` заменяет кнопку теста на «Вернуться к тесту» (`router.back()`).

**Тест урока: режим `lesson-test`.**
- Новый режим в quiz-session, очередь собирается из явного списка id без лимита длины сессии.
- После каждого ответа показывается разбор, как в практике.
- Итог: «Урок пройден», если 80% и выше, иначе «Нужно 80%».
- Ошибки сводятся в список «Перечитать шаг N: <название>».
- Дальше кнопки «Следующий урок» и «Итоговый тест», либо «Ещё раз».

**Итоговый тест курса: режим `course-test`.** Работает как экзамен — без разбора по ходу; итог сгруппирован по урокам.

**Экран курса: переделанный `/path/[topic]`.**
- Список уроков со статусами: «Шаг 3 из 7», «Тест 71% — нужно 80%», «Пройден · 86%». У следующего урока метка «Дальше».
- Внизу карточка итогового теста.

**Главная.** `TopicPathCard` показывает «Курс · Урок 3 из 6: Redux» и кнопку «Продолжить».

**Разбор вопроса.** Через `findQuestionStep` показывает «Урок: X · шаг N» вместо «Конспект: X».

### 6. Проверки (`scripts/verify-content.ts`) и паки

**`checkLessons` для формата `steps`:**
- шагов 4–8, `id` уникальны и в kebab-case;
- в шаге 1–3 блока, текст не длиннее ~600 символов;
- 1–2 вопроса теста на шаг, всего 5–8;
- каждый вопрос теста существует и имеет тег урока; один вопрос не повторяется в двух уроках курса;
- «Проверь себя»: 1–2 на урок, RU и EN заполнены, `answer` в допустимом диапазоне.

**`checkCourses`:**
- 10–15 вопросов, каждый урок курса покрыт;
- каждый вопрос существует, `tag` и `step` указывают на настоящий шаг.

**`checkIllustrations`:**
- корректный XML, `viewBox` шириной 280–360;
- белый список тегов, без `style`, `script`, `image`, `href` и `on*`;
- никаких «голых» цветов — только токены из списка, а для текста только цвета, у которых проверен контраст;
- `labels` совпадают с токенами в SVG, кириллица только в подписях;
- `font-size` не меньше 11, SVG не больше 8 КБ, заполнен `alt`.

**`checkDiagrams`:** для `tree` — `parent` указывает на узел выше по списку, глубина не больше 4, узлов не больше 7; использование схем учитывается и в уроках.

**`sanitize-pack.ts`:**
- урок проверяется по `format`;
- добавляются `illustrations` и `courses`;
- `tree` и `parent` принимаются;
- `PACK_SCHEMA` **не поднимаем**: старые версии просто отбросят новые уроки и покажут свои встроенные конспекты.

**`build-packs.ts`:** добавить `illustrations` и `courses`.

### 7. Контент пилота (`lessons/state.ts`)

| Урок | Шагов | Тест | Ключевые визуалы |
|---|---|---|---|
| state-basics | 6 | 7 | илл. «4 вида состояния», «id вместо копии»; деревья «рядом с местом использования», «подъём состояния», «проп-дриллинг → `children`» |
| state-immutability | 5 | 7 | илл. «общая ссылка после спреда», «мутирует / безопасно»; дерево «структурное разделение» |
| state-redux | 6 | 8 | цепочки «поток данных», «луковица middleware»; дерево «`combineReducers`»; илл. «селектор возвращает новый массив» |
| state-stores | 6 | 7–8 | деревья «далёкие потребители», «контекст перерисовывает всех», «подписка селектором»; илл. «атомы» |
| state-server | 6 | 8 | колонки «дедупликация»; цепочка «мутация → инвалидация»; илл. «жизненный цикл запроса», «гонка запросов» |
| state-url | 5 | 7 | илл. «анатомия URL»; цепочка «URL — источник правды»; колонки «push или replace» |

- Тесты собираются из существующих 60 вопросов темы, распределение по шагам предложил агент-архитектор.
- Шаг урока обязан содержать всё, что нужно для ответа на привязанные к нему вопросы. Это правило вносим в `content-guidelines` и проверяем вычиткой: машинно смысл не проверить.
- Новые вопросы, чтобы закрыть пробелы:
  - `state-url` — 3–4;
  - `state-stores` — 1 базовый;
  - «Проверь себя» — 9–10.
- Итоговый тест: 12 вопросов, по 2 на урок, не пересекаются с тестами уроков.
- Объём визуала — около 9 иллюстраций и 12 схем. При нехватке времени первыми режем «мутирует / безопасно» и «атомы».

### 8. Этапы (каждый — отдельный коммит, который можно выкатить)

1. **Основа без видимых изменений.**
   - Типы, `lib/lesson.ts`, `lib/illustration.ts`, пустые `ILLUSTRATIONS` и `COURSES`.
   - Sanitizer, `build-packs`, проверки в verify-content.
   - Версия не поднимается.
2. **Движок и урок 1 → 1.58.0.**
   - Пошаговый урок, «Проверь себя», `IllustrationView`, `tree` в `DiagramPlayer`, `$learning`, режим `lesson-test`, итог со ссылками на шаги, экран курса, карточка на главной, i18n.
   - Контент: урок `state-basics`.
3. **Механика итогового теста → 1.59.0.** После этого этапа остальной контент может доезжать паком.
4. **Аналитика.**
   - События `lesson_opened`, `lesson_closed {step_reached}`, `lesson_check_answered`.
   - Правка `site/privacy/index.html` (RU и EN): события и локальные данные «шаги уроков и результаты тестов». Публикуем до выхода версии.
5. **Уроки 2–6 и новые вопросы.** По коммиту на урок, patch-версии.
6. **`COURSES.state`** — контент итогового теста.
7. **Документация.** `content-guidelines` (уроки steps, SVG-иллюстрации, правило «тест ⊂ шаг»), `roadmap` (новый пункт), план в `docs/plans/`.

**Принятые по умолчанию решения:**
- старое правило «пройдено» сохраняем;
- тест урока — с разбором после каждого ответа, итоговый — как экзамен;
- «Проверь себя» не блокирует «Далее»;
- в первой версии только кнопки, без свайпа.

## Verification

На каждом этапе:
- `npm run verify:content` (вместе с type-check) проверяет код возврата; перед релизом — `-- --links`.

**Совместимость паков:**
- собрать пак `npm run build:packs -- --out <scratchpad>`;
- прогнать его через `sanitize-pack.ts` из 1.57: уроки state должны отброситься, число вопросов — не уменьшиться;
- новый sanitizer должен принять пак целиком.

**Эмулятор**, 360dp, светлая и тёмная тема, акценты `state` и `javascript`:
- иллюстрации с цветами из токенов;
- шаги вперёд и назад, `?step=`;
- «Проверь себя»;
- тест сдан и не сдан → «Перечитать шаг» → «Вернуться к тесту»;
- статусы на экране курса и карточка на главной;
- после перезапуска прогресс сохранён;
- «Сбросить прогресс» очищает и уроки;
- старый урок (`closures`) выглядит как раньше.

**Сценарий обновления:** установить 1.57 с пройденными разделами state, обновить приложение → разделы остаются пройденными, достижения повторно не всплывают.
