# R3-3, шаг 1 — тема «HR и поведенческое интервью»: план

Составлен 14.10.2026 как передача в новую сессию. Размер M–L: новая тема (инфраструктура S) + ~35 вопросов и 5–6 конспектов RU+EN. Версия — minor.

## Зачем

Первая тема из очереди R3-3. HR-этап проходят все кандидаты, а готовятся к нему меньше всего; для новичка это самая частая причина отказа после технички.

## Инфраструктура (S)

Новая тема регистрируется в шести местах — компилятор подскажет остальные:

- `shared/config/topics.ts` — `TopicId` + `TOPIC_IDS` (`'hr'`, префикс id вопросов `hr`).
- `entities/topic/config/topics.ts` — `TOPICS.hr`: `shortTitle: 'HR'`, название «HR и поведенческое интервью» / «HR & behavioral», описание.
- `entities/topic/config/directions.ts` — тема в `frontend.topics` (HR общий для всех направлений; когда появится второе — решить: дублировать тему в каждое направление или вынести в «Общее»; `checkDirections` сейчас требует ровно одно направление).
- `shared/theme/colors.ts` — акцент `hr` (light/dark, контраст ≥ 4.5 проверит `verify-content`); не фиолетовый (пользователь не любит). Кандидат — тёплый терракотовый.
- `entities/topic/ui/topic-logo.tsx` — логотип (геометрия, без шрифта: например, два «пузыря» диалога).
- `scripts/verify-content.ts` — `ID_PREFIX.hr = 'hr'`.
- `entities/question/config/paths.ts` — путь по теме; `config/tags.ts` — теги.

## Теги (6)

| Тег | Что внутри |
| --- | --- |
| `self-presentation` | «Расскажите о себе»: структура настоящее → прошлое → будущее, 1–2 минуты, связь с вакансией |
| `star` | Метод STAR: ситуация, задача, действия, результат; «я», а не «мы»; измеримый результат |
| `tough-questions` | Провалы, конфликты, слабые стороны, увольнение с прошлого места — честно и с выводом |
| `motivation` | Почему эта компания и роль, планы на 3–5 лет, ожидания по зарплате (вилка, рынок) |
| `questions-to-employer` | Что спросить в конце: процессы, онбординг, команда, критерии успеха на испытательном |
| `process` | Этапы найма, сопроводительное, тестовое, оффер и его сравнение, испытательный срок |

На каждый тег — конспект (`verify-content` требует). Источники — первоисточники по найму: Google re:Work (структурированные интервью), MIT CAPD / Harvard Career Services (STAR), hh.ru/Хабр Карьера (рынок, зарплатные вилки).

## Формат вопросов

«Один верный ответ» в HR достижим, если спрашивать не «что ответить», а **какой ответ сильнее и почему**:

- **choice** (основа, ~25): «Интервьюер спрашивает „Почему уходите?“. Какой ответ сильнее?» — 5 вариантов, дистракторы — типичные ошибки (критика бывшего работодателя, «из-за денег» без контекста, неуверенность, перебор деталей). Разбор — почему верный работает с точки зрения интервьюера.
- **order** (~6): шаги STAR, структура самопрезентации, этапы найма, порядок действий при получении двух офферов.
- **bug-line** (~4): самопрезентация или ответ по STAR построчно — «какая строка портит ответ» (пример: «В прошлой команде все были некомпетентны»).
- `verify` машинно не применим — сверка с источниками, как у React/Web.

Тексты — без канцелярита, примеры из фронтенда (миграция на TypeScript, ускорение сборки, конфликт на код-ревью). EN — смысловой перевод, не дословный.

1. Инфраструктура темы + 6 тегов + путь + акцент/лого → `verify-content`, эмулятор (шторка, главная, лого в light/dark).

4. Версия по скиллу `release-notes`, docs (roadmap R3-3, progress, content-guidelines — раздел про HR-вопросы «какой ответ сильнее»), коммит.

## Риски

- Субъективность: если для варианта нет аргумента из источника — вопрос не брать.
- Объём EN: по В-2 решено EN для новых тем пока делать; если пользователь решит иначе — HR можно оставить RU-only только после правки `verify-content` (сейчас RU и EN обязательны).
