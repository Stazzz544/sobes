# Sobes — план развития

Обновлено 14.10.2026. Как пользоваться — раздел «Как работаем» в конце.

## Цель

Sobes — карманный тренажёр, который ведёт новичка в IT от первых вопросов до уверенного собеседования на junior. Сначала фронтенд, затем другие направления. Доход — freemium: учёба для новичка бесплатна всегда, Pro продаёт скорость и удобство. Платежи — позже, архитектуру под них закладываем заранее.

## Принципы

1. Качество контента — главный актив: один верный ответ, первоисточники, машинная проверка где возможно (`docs/content-guidelines.md`).
2. Офлайн-first: всё работает без сети; сеть — только для обновления контента и внешних ссылок.
3. Без рекламы и тёмных паттернов (навязчивые пейволлы, фейковые «осталось 2 часа»).
4. Базовая учёба бесплатна навсегда — Pro не отнимает у новичка возможность выучить материал.
5. Приоритеты и монетизация — по метрикам, не наугад.
6. Основной язык — RU (RuStore); EN поддерживаем (см. В-2).

## Где мы сейчас (14.10.2026)

Есть: 7 тем, 275 вопросов RU+EN; режимы практика / популярные / сложные / собеседование на время / работа над ошибками / интервальное повторение («Повторить сегодня» на главной); цель на день и серия с заморозкой; разбор с источниками и схемами; «Спросить ИИ» во внешний сервис; статистика; light/dark; `verify-content` и CI на GitHub; release-подпись, сплэш, политика конфиденциальности; аналитика и отчёты о сбоях AppMetrica (ждут ключ) с отключением в настройках; экран «Что-то пошло не так»; шаблоны issue и CONTRIBUTING.

Чего нет / что мешает:

- не опубликовано в RuStore (R0-7, R0-9 — за пользователем), нет ключа AppMetrica (R1-1);
- контент вшит в бандл — новый вопрос = новый релиз (R3-1);
- нет теории и пути по теме — только вопросы (R2-2, R2-3);
- нет напоминаний (R2-6, нужен `expo-notifications`);
- прогресс только на телефоне (R4-4, точка Б);
- структура «тема = навык фронтенда» не готова к другим направлениям (R3-2);
- `FEEDBACK_EMAIL` пуст — «Сообщить об ошибке» уходит в Share (R0-4); лицензии в репозитории нет.

## Метрики

Считаем после R1-1. Стартовые ориентиры, уточним по данным:

- удержание D1 / D7 / D30 — ориентир 25% / 10% / 4%;
- доля завершённых тренировок, вопросов на активного пользователя в день, WAU;
- качество вопроса: доля ошибок и «Не знаю», перекос в один дистрактор, жалобы — кандидаты на переписывание;
- критерий старта монетизации (этап 5): стабильно ≥ 1000 активных в неделю и D30 не падает.

## Как работаем

- `docs/roadmap.md` — что и зачем делаем, по порядку. `docs/progress.md` — что сделано, как проверено, гочи.
- Сессия: прочитать roadmap → взять первый открытый пункт текущего этапа (или названный пользователем) → оценка S/M/L и короткий план → реализация → проверка → статус здесь + запись в progress.md → коммит только по команде.
- Порядок: этапы 0 и 1 — первыми; 2 и 3 параллельно (функции и контент); 4 — когда есть что показывать; 5 — по критерию (R5-1 — в любой момент).
- Проверка: `npm run type-check`; контент — `npm run verify:content` (перед релизом `-- --links`); UI — эмулятор 360 dp, light и dark.
- 📦 — только с разрешения; нативные пакеты — через `npx expo install`.
- Пересмотр плана — после каждого этапа или раз в месяц: метрики → перестановка приоритетов → запись в журнал решений.
