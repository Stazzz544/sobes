# Версия и «Что нового»

Каждая заметная пользователю правка выходит с новой версией. История показывается в приложении: Настройки → «О приложении» → «Версия X.Y.Z · Что нового» (экран `app/releases.tsx`, виджет `release-notes`).

## Какую версию

- **minor** (`1.1.0 → 1.2.0`) — новая фича, пункт roadmap, пачка новых вопросов или конспектов.
- **patch** (`1.2.0 → 1.2.1`) — исправления, правки текстов и вопросов, мелкие улучшения UI.
- **major** — только по решению пользователя.
- Несколько фич в одной сессии до коммита можно собрать в одну версию, но каждый коммит с изменениями в приложении должен оставлять версию и заметки согласованными.

## Шаги

1. `npm version minor --no-git-tag-version` (или `patch`) — правит `package.json` и `package-lock.json`. `versionCode` считается в `app.config.ts` сам.
2. Добавить релиз **в начало** `RELEASES` в `src/shared/config/releases.ts`: `version`, `date` (`YYYY-MM-DD`, сегодня), `changes` — 1–4 пункта `{ ru, en }`.
3. Добавить секцию `## X.Y.Z` в начало `CHANGELOG.md` — те же пункты по-русски (это текст «Что нового» для RuStore).
4. `npm run verify:content` — `checkReleases` сверяет версию в `package.json` с первой в `RELEASES` и наличие секции в `CHANGELOG.md`, проверяет порядок версий и дат, пустые пункты.
5. Закоммитить вместе с фичей.

## Как писать пункты

- Языком пользователя, а не разработчика: что появилось или изменилось на экране. Без имён файлов, сторов и номеров задач.
- Коротко: одна строка, начинается с сути («Новые типы вопросов: …», «Исправлено: …»).
- Числа — только проверенные (`npm run verify:content` печатает число вопросов).
- Внутренние правки (CI, рефакторинг, docs) в заметки не попадают и версию не двигают.
